# VMTech AI outcomes

- [x] **General assistant experience** — VMTech AI provides skill choices for automation drafts, code debugging, teaching/explanations, learning plans, project/business plans, and general questions. It presents plans and code as drafts; it does not claim to execute workflows or run code.
- [x] **Responsive assistant UI** — Keep the skill navigation, prompt examples, chat composer, loading/error/retry states, copy control, new-chat behavior, mobile layout, brand, and route manifest. Desktop/mobile layouts were reviewed in the design pass; the local-model readiness indicator and setup notice now reflect the runtime. TypeScript and production-build checks pass.
- [x] **Own local AI, no third-party inference API** — Replace the Manus-managed LLM call with a private Ollama runtime running downloaded open-weight Qwen 3.5 model files locally. The default is `qwen3.5:9b`; document `qwen3.5:4b` for lower-memory machines. Do not require a provider account, API key, or paid cloud AI service. Reject public inference hosts and HTTP redirects before sending prompts. Do not silently fall back to cloud inference. Be clear that this is a local open-weight model, not a foundation model trained from scratch. A real Qwen 3.5 4B answer was generated through the app's tRPC route.
- [x] **Independent self-hosted runtime** — Provide a Docker Compose app plus Ollama service; retain downloaded model weights in a persistent local volume, keep Ollama's service port private to the Compose network, and bind standalone starts to loopback by default. The container may listen internally on all interfaces only behind the loopback-only host port mapping. Include an optional NVIDIA Docker override for compatible hosts. Start and run the app without Manus OAuth, Manus AI, Manus platform browser config, API credentials, or a managed database. The app was smoke-tested with the local model; Compose files were formatted/inspected but could not be executed because Docker is not installed in this sandbox.
- [x] **Local model operation and errors** — Use validated, size-bounded chat input and a bounded local inference request. If Ollama is offline or the configured model is missing, show a helpful error with the setup/retry action; never pass the prompt to a remote model or claim success without a local answer. Retain stale-response protection and per-client throttling. The assistant must not falsely claim inference runs on the end user's device or is fully offline; when asked, explain the operator-supplied deployment context accurately.
- [x] **Self-host documentation** — Provide `.env.example` and `LOCAL_AI.md` covering Docker/Compose setup, first-time model download, quality vs. memory choice, CPU/GPU trade-offs, safe networking, persistence, updating, and shutting down. Do not commit multi-GB model weights.
- [x] **No unnecessary external UI requests** — Remove remote-font dependency and the live Manus/OAuth integrations from application startup and browser bootstrap. A model-weight download during installation is allowed; inference remains on the owner's machine/server.
